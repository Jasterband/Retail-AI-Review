## 1. 必须先有的（没有就很难正经开发）

| # | 前置条件 | 说明 | 状态 |
|---|----------|------|------|
| 1 | **接口约定冻结** | PE simple 以 [README-PE-simple对接.md](README-PE-simple对接.md) 为准；四种 `overall_status`、`photo_type` 枚举与请求体对齐后再大改字段 | ☐ |
| 2 | **材料可读** | 约定 S3 桶/路径/读权限；本地开发可用样例目录模拟 `file_url` | ☐ |
| 3 | **合格样例 + 表单** | 大讲堂/微型合格照片，并整理成可构造的 `form`（日期、地点、讲者名等与图一致） | ☐ |
| 4 | **规则实现优先级** | 先做哪些规则（建议：Logo/人数 → 关键字段 → 台卡/手册/PPT），避免第一周铺开全部 | ☐ |
| 5 | **运行与模型通道** | 可部署的服务环境；OCR/多模态/检测所需的 API Key 或内网模型可达 | ☐ |

## 2. 强烈建议有的（影响质量与上线）

| # | 前置条件 | 说明 | 状态 |
|---|----------|------|------|
| 6 | **模版 pack（crop）** | 从合格样例裁出海报/台卡/手册封面/微型 PPT 特征图，见 [04-template-pack.md](04-template-pack.md)；本地缺独立手册图需补 | ☐ |
| 7 | **负样本** | 模糊、错模版、台卡缺人、人数不够、**主题与历史重复**、无 Logo 等，见 [05-golden-set.md](05-golden-set.md) | ☐ |
| 8 | **黄金集表单** | 每场样例一份「期望全 PASS」的 Request JSON；姓名以台卡/海报为准（注意笔误） | ☐ |
| 9 | **异步任务能力** | 队列或后台 Worker；提交接口只受理，审核在后台跑 | ☐ |
| 10 | **结果落库** | AI 专用库：最终结果给 PE；中间结果供 debug；见 [技术选型与数据存储.md](技术选型与数据存储.md) | ☐ |

## 5. 建议启动顺序（最小闭环）

1. 起服务：`POST /v1/retail_meeting_checks` 校验并落库 → 返回 `202`；`GET /v1/retail_meeting_checks/{task_id}` 可查状态  
2. 能按 `file_url`（或本地映射）下载到真实图片  
3. 接入 **一条** 真实规则（如 Logo），写入 `rule_results`  
4. 用一场微型样例跑通：提交 → 轮询 → 终态 `PASS`/`FAIL`  
5. 再按 [03-rule-matrix.md](03-rule-matrix.md) 加台卡、人数、手册、PPT 模版等  
6. 补模版 pack + 负样本，校准阈值与 `NEED_HUMAN`  

---

## 6. 一句话标准

**接口约定 + 能读到的图 + 样例与表单对齐 + 模型/OCR 可用 + 异步与落库** —— 五样齐了可以正经开干；模版 crop 与负样本紧随其后，上线前必须具备。
